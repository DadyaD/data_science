# Прогнозирование остаточного ресурса авиадвигателя (NASA CMAPSS FD001)

Пет-проект в области predictive maintenance: по телеметрии двигателя
(21 датчик, циклы работы) предсказывается остаточный ресурс до отказа
(RUL, Remaining Useful Life).

**Результат: финальный test RMSE 17.92 цикла** (CV RMSE 18.70 ± 0.59,
GroupKFold по двигателям).

## Постановка задачи

Остановка оборудования в эксплуатации дороже, чем обслуживание по
состоянию. Задача — по потоку показаний датчиков оценить, сколько циклов
работы осталось до отказа, чтобы планировать обслуживание заранее.

Формально: регрессия RUL по показаниям сенсоров на последнем
записанном цикле двигателя.

## Данные

[NASA Turbofan Engine Degradation (CMAPSS)](https://www.nasa.gov/intelligent-systems-division/discovery-and-systems-health/pcoe/pcoe-data-set-repository/),
поднабор **FD001**: 100 обучающих и 100 тестовых двигателей,
21 сенсор + 3 параметра режима, запись по циклам.

- В train история каждого двигателя оборвана в момент отказа —
  это позволяет построить таргет.
- В test запись оборвана до отказа; истинный остаток жизни —
  в файле RUL_FD001.txt (это закрытая тестовая метка).
- FD001 содержит один тип отказа — деградация компрессора высокого
  давления (HPC).

Идентификация датчиков выполнена физически: например, sensor_9 —
частота вращения ротора (~9000 об/мин), что подтверждено характером
распределения.

## Методология

1. **EDA**: траектории сенсоров по двигателям, распределение ресурса,
   выявление деградационных трендов.
2. **Чистка признаков**: отброшены каналы со стандартным отклонением
   &lt; 0.01 (в том числе sensor_5, 6, 16 — константы в FD001).
3. **Таргет**: RUL = (макс. цикл двигателя − текущий цикл), ограничен
   сверху 125 циклами — кусочно-линейная модель деградации NASA:
   двигатель «как новый» держит ресурс, затем износ нарастает.
4. **Валидация**: GroupKFold (n_splits=5) с группировкой по engine_id —
  исключена утечка между фолдами; признаки строятся без просмотра
   будущего (скользящие окна без center).
5. **Подбор гиперпараметров**: GridSearchCV; перебор остановлен по
   принципу «разница в пределах статистического шума (±0.6)».

## Результаты

| Модель | Признаки | CV RMSE | Test RMSE |
|---|---|---|---|
| Линейная регрессия | сырые сенсоры | — | ~21 |
| LightGBM (500 деревьев) | сырые сенсоры | — | 17.81 |
| LightGBM | + rolling W=5 (ma, dev) | 18.70 | 18.29 |
| LightGBM (тюнинг) | + rolling W=15 | 18.72 | — |
| **LightGBM (тюнинг)** | **сырые сенсоры** | **18.70** | **17.92** |

### Ключевые находки

- Инженерные признаки (скользящие средние и отклонения, окна 5–15)
  **не дали прироста** над сырыми сенсорами при использовании
  градиентного бустинга — результат подтверждён на трёх независимых
  проверках (два протокола на test, CV на двух конфигурациях).
  Гипотеза: деревья сами извлекают нелинейные зависимости, а на выборке
  из 100 двигателей дополнительные признаки вносят шум.
- Тюнинг склонялся к более слабым моделям (меньше листьев, меньший
  learning_rate) — признак лёгкого переобучения на маленьких данных.
- Ближе к отказу точность модели не превышает наивный константный
  прогноз — для применения нужен каскад «детектор зоны риска + регрессия».

## Планы развития

**Модель для конкретного типа отказа.** FD001 содержит один тип неисправности — деградацию компрессора высокого давления. Следующий шаг: обучить модель на подмножестве сенсоров, физически связанных с компрессором, и проверить гипотезу о её большей точности. Одновременно прогнать текущую модель «чужого» типа отказа — набора FD003 (отказы вентилятора) без переобучения. Ожидаемое ухудшение метрик — практическое обоснование ключевой архитектурной идеи: **единая модель RUL не универсальна, нужен классификатор типа отказа (маршрутизатор), направляющий двигатель на специализированную модель**.

**Анализ остальных наборов данных.** FD002 и FD004 содержат шесть разных рабочих режимов (в отличие от одного режима FD001) — это отдельная задача нормировки сенсоров относительно режима, без которой кластеризация развалится по условиям работы, а не по типам неисправностей. После нормировки — кластеризация паттернов деградации на FD004, где два типа отказа смешаны и не размечены: **кластеры, совпадающие с истинными типами неисправностей, станут обучающими метками для маршрутизатора**.

**Итоговая система:** телеметрия → (нормировка по режиму) → классификатор типа отказа → специализированная модель RUL → планирование обслуживания.
